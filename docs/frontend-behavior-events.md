# Frontend behavior events (#95 and #96)

The feed creates real LATEST result pages. Each returned card retains its page's resultContextId and zero-based position; appending another page does not shift positions. Public card rendering uses the existing hero component, actual server progress and signed photo URL. Exact student lookup precedes profile collection, independently of whether public cards exist. Unavailable relationship totals and private balances are omitted. The backend identifies the actor; the frontend never infers self identity from a nickname or Persona mapping. SELF_PROFILE_VISIT is terminal and stores no visit on the backend.

POST /api/behavior/context verifies academy access using the current authenticated account list. HttpOnly Persona epochs rotate on every selection, including A → B → A. Academy selection has its own epoch. The private X-Crabit-Behavior-Context header binds the request to the cookie snapshot and academy; the generic BFF rejects missing or mismatched behavior contexts before contacting upstream. Existing legacy Persona sessions use a sentinel epoch until a real Persona selection; bootstrap never writes a Persona epoch, so a delayed bootstrap cannot overwrite a newer selection. Context mismatch disposes the old session and reloads authenticated data. The private header is not an authentication credential and is never forwarded upstream.

A persistent feed layout owns each committed route entry and preserves it through React effect replay. Exact-student success emits one visit; rerender/refocus alone does not. Departure, reload, back navigation and persisted page restoration establish fresh entries. Late responses are ignored. Link clicks are independent events and never prevent default navigation. Exposure requires 50% continuous visible-document intersection for 1000ms. Hidden state or actual exit resets the cycle; DOM attachment replay preserves its impression identity and resets unobservable dwell time.

Delivery is memory-only: at most 100 queued, in-flight or retrying events per route queue; overflow drops the new event. A request times out after 10 seconds. Network/timeout and HTTP 408, 429, 500, 502, 503, 504 retry after 1, 2, 4 seconds, at most four total attempts. Valid Retry-After can lengthen that delay within the remaining lifetime. Serialized event bytes, identifiers, occurrence time and collection context never change. Other failures are terminal. Original occurrence age is bounded to 24 hours and feed events also expire with their result context. Departure and refresh discard unsent/retry work; already dispatched requests can finish under their captured context. Refresh retains those in-flight requests in the queue's capacity count until they settle. Late mismatch responses from discarded events or superseded reads cannot restart the replacement session. There is no persistent or offline queue.

The exact imported backend contract is commit 56ef70bc25b4470038f3ffb417ca6d8acb48e61c, with byte digest recorded in openapi/provenance.json. That contract replaces the removed friendship-request API; unused old HTTP wrappers were replaced with current search/exact-student operations, errors were synchronized, and the sharing option now uses FOLLOWERS. Wish fixtures explicitly include photo: null.

Validation uses behavioral Vitest tests and Playwright scenarios against a real production Next server with an isolated local HTTP backend fixture. Browser scenarios cover dwell/click/profile events, distinct reload/back entries, appended-page context and zero-based position, refresh, academy and Persona A → B → A rejection before upstream, delayed stale reads, inaccessible profiles and immutable retries without breaking navigation. Fixture acceptance is not Spring/PostgreSQL storage verification. Production integration and storage replay read-back are separate checks. This change does not implement full profile statistics, relationship actions, recommendations, merge or deployment.
